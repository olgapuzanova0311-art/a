# Подбор товаров для маркетплейса (Wildberries / Ozon)

Навык описывает воспроизводимый алгоритм: от гипотезы ниши до решения "запускать / не запускать" с юнит-экономикой. Работает по обоим маркетплейсам; данные предполагаются из MPStats или аналогичных сервисов аналитики (при их отсутствии — из открытых карточек WB/Ozon вручную, см. раздел "Если нет доступа к MPStats").

Стиль вывода на всех этапах: **наблюдение → цифра → вывод/рекомендация → контрольная метрика**. Это формат, к которому пользователь уже привык в других аналитических отчётах — придерживайся его.

## Когда применять полный алгоритм, а когда — часть

- Если пользователь даёт готовую нишу/товар и просит "посчитай, стоит ли" — начинай сразу с Шага 3 (глубокий анализ) и Шага 4 (юнит-экономика).
- Если пользователь просит "найди нишу" без конкретики — проходи все шаги 1→4.
- Если пользователь просит сравнить 2-3 конкретных товара — Шаги 3-4 для каждого, затем сводная таблица и рекомендация.

Перед началом уточни у пользователя (если не указано в запросе), максимум 2-3 вопроса, не больше:
1. Бюджет на закупку первой партии (влияет на минимальный порог по марже и обороту ниши).
2. Есть ли ограничения по нише (не готова работать с хрупким/крупногабаритным/сезонным товаром, есть предпочтения по категории).
3. Какой маркетплейс приоритетнее для этого запуска (или оба).

Не спрашивай больше — если ответа нет, работай с разумными допущениями и явно их проговаривай в отчёте.

## Шаг 1. Постановка рамки поиска

Зафиксируй в начале отчёта:
- Бюджет на закупку + логистику первой партии.
- Целевой маркетплейс(ы).
- Исключённые категории (если есть).
- Горизонт: ищем сезонный товар под конкретную дату или круглогодичный.

## Шаг 2. Поиск и первичный отбор ниш

Цель — найти категории/подкатегории с сочетанием "спрос есть, конкуренция слабая или неоднородная".

Ключевые метрики по категории (из MPStats-подобных данных):
- **Оборот категории/подкатегории за 30-90 дней** (руб.) и динамика к предыдущему периоду.
- **Количество продавцов (SKU) в подкатегории** и их динамика — резкий рост числа продавцов при том же обороте = усиление конкуренции.
- **Доля топ-10 продавцов в обороте категории** — если топ-10 забирают >70%, ниша концентрированная, входить сложнее, если <40% — фрагментированная, легче найти место.
- **Средний чек** и разброс цен (квартили) — большой разброс часто означает несформированный рынок и место для нового позиционирования.
- **Средний рейтинг и количество отзывов у карточек в топе** — если у топа мало отзывов (<50-100) при высоком обороте, это сигнал молодой ниши.
- **Сезонность** по графику продаж за 12 мес — избегать входа в пик сезона без учёта спада после.
- **Индекс конкуренции** (если сервис даёт готовый) или расчётный: обороты категории / число активных SKU — чем выше значение на 1 SKU, тем привлекательнее.

Для каждой найденной ниши-кандидата фиксируй в формате наблюдение → цифра → вывод:
> Оборот подкатегории «X» вырос за 90 дней на 34%, число продавцов — только на 9%. Спрос обгоняет предложение → ниша перспективна для входа. Контроль: пересчитать через 30 дней после запуска, если рост продавцов ускорится >20%/мес — маржа будет схлопываться.

Отбирай 3-7 ниш-кандидатов для Шага 3, не углубляйся в каждую сразу целиком.

### Критерии первичного отсева (стоп-факторы)
- Категория под жёстким регулированием (сертификация, маркировка "Честный знак" для новичка без опыта) — если бюджет и время пользователя не позволяют, отсеивать.
- Крупногабаритный/хрупкий товар при отсутствии у пользователя логистических возможностей — уточнить, а не отсеивать автоматически.
- Падающий тренд оборота 2+ квартала подряд без сезонного объяснения.

## Шаг 3. Углублённый анализ товара-кандидата внутри ниши

Для каждого кандидата, прошедшего Шаг 2:

**3.1 Конкурентный бенчмаркинг карточек-лидеров (топ-10-20 по обороту в нише)**
- Цена, скидка/СПП, рейтинг, число отзывов, число фото/видео в карточке, наличие рич-контента.
- Возраст карточки (когда появилась) — если весь топ старше 12 мес, вход новичка сложнее без сильного УТП.
- Из чего складывается позиционирование лидеров (какие боли/выгоды вынесены в заголовок и инфографику).

**3.2 Анализ отзывов и вопросов покупателей по нише**
- Собрать повторяющиеся жалобы (боли) на товары-лидеры — это прямой источник УТП для нового товара.
- Собрать частые вопросы без ответа в карточках — сигнал недостатка информации у конкурентов.

**3.3 Ценовой сегмент и позиционирование**
- Определить, в каком ценовом сегменте (низкий/средний/премиум) свободнее место, исходя из квартилей Шага 2 и качества карточек лидеров в каждом сегменте.

**3.4 Поставщик и себестоимость**
- Ориентировочная закупочная цена (если пользователь не дал — явно пометить как допущение и предложить диапазон по аналогам).
- МОQ (минимальная партия) поставщика, если известно.

Вывод по каждому кандидату — короткий (3-5 пунктов), детальный расчёт только для финалистов на Шаге 4.

## Шаг 4. Юнит-экономика

Считать на 1 единицу товара для целевой розничной цены (обычно медиана ниши из Шага 2, можно взять сценарии: пессимистичный/базовый/оптимистичный).

Обязательные статьи расходов — используй актуальные тарифы маркетплейса, если пользователь их не предоставил, явно спроси или помечай как допущение с указанием, что ставки нужно сверить в личном кабинете (тарифы WB/Ozon регулярно меняются):

| Статья | Комментарий |
|---|---|
| Закупочная цена | из Шага 3.4 |
| Логистика до склада МП | зависит от региона поставки |
| Логистика МП до покупателя (комиссия за доставку) | тариф зависит от габаритов, склада, категории |
| Комиссия маркетплейса за категорию | % от цены продажи, разный на WB и Ozon и по категориям |
| Эквайринг/прочие комиссии | если применимо |
| Хранение на складе МП | за период оборачиваемости |
| Упаковка/маркировка | включая "Честный знак" при необходимости |
| Реклама/продвижение (внутренняя + внешний трафик) | заложить % от выручки на старте выше, чем на устоявшейся карточке |
| Налог ИП (УСН и т.п.) | по системе налогообложения пользователя |
| Возвраты/брак | % от партии, закладывать по среднему для категории |

Итог:
- **Маржинальность на единицу** = Розничная цена − сумма расходов выше.
- **Точка безубыточности по объёму** = Постоянные разовые расходы (партия+продвижение запуска) / маржа на единицу.
- **ROI на вложенный капитал** за оборачиваемость партии (не путать с маржой — считать с учётом скорости оборота денег).

Дай три сценария (пессимистичный / базовый / оптимистичный) по цене продажи и рекламным расходам, а не одну цифру.

Подробные формулы и разбивка по каждому МП — см. `references/unit-economics-formulas.md`.

## Шаг 5. Итоговый скоринг и решение

Свести кандидатов в одну таблицу:

| Товар/ниша | Оборот ниши | Индекс конкуренции | Маржа (баз. сценарий) | ROI | Стоп-факторы | Решение |
|---|---|---|---|---|---|---|

Решение — одно из: **запускать / запускать с оговоркой (указать условие) / не запускать (указать причину)**.

Для выбранного товара — зафиксировать 3-5 контрольных метрик, которые пользователь должен отслеживать после запуска (оборачиваемость, динамика конкурентов, изменение СПП/комиссии, отзывы), и через какой период их пересматривать (обычно 2-4 недели после запуска).

## Если нет доступа к MPStats

Если у пользователя нет аналитического сервиса и данных нет в контексте:
- Работай по открытым данным карточек WB/Ozon (цена, отзывы, рейтинг, число товаров в выдаче по ключевому запросу) — это даёт приближённую, а не точную картину конкуренции и оборота.
- Явно пометь в отчёте, какие цифры — оценка/допущение, а какие — из реального источника.
- Предложи, если у пользователя есть свои Google Apps Script интеграции с API WB/Ozon (уже использовались ранее для выгрузки цен и товаров) — использовать их для выгрузки реальных данных по ценам и остаткам, а обороты/конкуренцию оценивать по косвенным признакам (частота обновления цен, число отзывов в динамике).

## Формат финального отчёта

1. Рамка поиска (Шаг 1) — 3-5 строк.
2. Таблица ниш-кандидатов с ключевыми метриками (Шаг 2).
3. Короткие карточки по каждому финалисту (Шаг 3) — наблюдение → цифра → вывод.
4. Юнит-экономика по сценариям для 1-2 финалистов (Шаг 4).
5. Сводная таблица и решение (Шаг 5).
6. Контрольные метрики и срок следующего пересмотра.

Не растягивай отчёт бесмысленным текстом между цифрами — пользователь ценит плотность данных и конкретику, а не эссе.
