# Публикация на GitHub и Railway

Доступы в переменных окружения: `GH_TOKEN` (GitHub, все репозитории Ольги, аккаунт olgapuzanova0311-art) и `RAILWAY_API_TOKEN` (Railway, всё рабочее пространство). Команды `gh`, `git` и `railway` уже настроены. Перед незнакомой командой Railway смотри `railway <команда> --help`, флаги меняются между версиями.

## Быстро: страница рядом с сайтом интенсива
Для одиночной страницы проще всего навык site-builder, шаг 7: файл в `docs/sites/<имя>.html` основного репозитория, ссылка `https://agent.olgapuzanovva.ru/sites/<имя>.html`.

## Отдельный сайт или проект: свой репозиторий + Railway
1. Собери проект в `~/projects/<имя>` (латиница, дефис). Для статичного сайта: `index.html` и рядом пустой файл `Staticfile`.
2. Репозиторий: `cd ~/projects/<имя> && git init -b main && git add -A && git commit -m "Первая версия"`, затем `gh repo create olgapuzanova0311-art/<имя> --private --source . --push`. Если GitHub ответит, что не хватает прав на создание репозитория, скажи Ольге: в токене нужно включить Administration → Read and write; пока опубликуй на Railway без GitHub (шаг 3, `railway up`).
3. Railway:
   `railway init --name <имя>` (новый проект в рабочем пространстве Ольги; если спросит workspace, укажи флагом из `railway init --help`),
   `railway up --detach` из папки проекта (загружает и собирает код),
   `railway domain` (выдаёт адрес вида https://<что-то>.up.railway.app).
   Чтобы Railway сам обновлял сайт при каждом пуше в GitHub, подключи репозиторий к сервису (`railway --help`, раздел про source/connect) или скажи Ольге нажать Connect Repo в настройках сервиса.
4. Проверь `curl -sI <адрес>`: должен быть 200. Если сборка упала: `railway logs --build` и `railway logs`, исправь и повтори `railway up`.
5. Пришли Ольге ссылку на сайт, ссылку на репозиторий и коротко что где лежит. Запиши проект в agent/MEMORY.md (имя, репозиторий, адрес).
